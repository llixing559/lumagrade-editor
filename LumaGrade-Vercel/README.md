# LumaGrade

一款在浏览器本地运行的在线 LUT 修图工具。

## 功能

- 导入 JPG、PNG、WebP 图片
- 10 款经过资料研究与样片校准的内置 33³ LUT
- 解析并应用用户自己的标准 3D `.cube` LUT
- 使用至少 12 张完成调色的参考成片，无需原图对照训练专属 33³ LUT
- 逐张提取屏幕阶调、色相响应、RGB 光谱倾向近似、色彩分离、饱和度、
  灰阶层次与全局反差，导出标准 35,937 节点 `.cube`
- 内置预设强度、用户 LUT 强度与基础曝光、色彩调节
- 默认开启逐图“智能匹配”：在套 LUT 前自动校正安全范围内的曝光、白平衡和反差，
  套 LUT 后再进行阴影、高光与通道溢出保护
- 自动分析值会直接写入右侧曝光、色温、色调、反差、高光和阴影滑杆；
  所有手动滑杆使用真实逐像素处理，预览与导出结果一致
- 可选 AI 智能扫描：允许用户填写自己的 API 接口、模型和密钥，自动识别并调用
  GPT、Gemini、DeepSeek、豆包、Claude 与常见 OpenAI 兼容模型
- 可选联网参考匹配：按“徕卡 M9”等 LUT 名称检索官方资料、专业评测和公开讨论，
  将可追溯的色彩共识作为低权重先验，并在界面展示来源
- 实时 RGB 直方图
- 原图对比、撤销与重做
- 全分辨率 JPG 导出

内置预设包含 Portra 400、Gold 200、Vision3 250D、Provia 100F、
Velvia 50、FUJI CC、FUJI NC、Hasselblad、Leica Classic 和 Tri-X 400。
胶片预设采用公开数据表驱动的光谱模拟；专有相机色彩采用官方描述和官方样片校准的参考 LUT。
PROVIA、Velvia 和 Classic Chrome 使用 Fujifilm 官方 F-Log2 Film Simulation LUT
转换并适配普通 sRGB 照片。
详细依据与边界说明见 [LUT_SOURCES.md](./LUT_SOURCES.md)。

照片和 LUT 默认在用户浏览器内处理。只有用户主动开启 AI 智能扫描，并且所选模型
具有视觉能力时，才会把明确标注数量的压缩预览发送给用户填写的 AI 接口；文本模型
只接收本地聚合统计。

## 智能匹配

LUT 本身只有固定的 RGB 映射，不知道当前照片是否欠曝、偏色或已经接近高光溢出。
编辑器会先分析当前照片和所选 LUT 的组合，再计算每张照片独立的输入校正与输出保护：

- 输入阶段：场景感知曝光、有限幅度白平衡、反差和暗部层次；
- LUT 阶段：照常应用内置或用户导入的 33³ LUT；
- 输出阶段：补偿 LUT 引入的明度漂移，并压缩将要溢出的高光、抬起堵塞的暗部。

“智能匹配”默认开启，可在右侧调整面板关闭或重新分析。自动结果会写入下方滑杆，
实时预览和全分辨率导出使用同一份分析结果。算法只做全局校正，不会假装识别局部
主体；舞台低调、剪影和刻意偏色场景会受到安全阈值保护，但仍建议用户按创作意图微调。

## AI 智能扫描与多厂商 API（可选）

项目提供服务端 `/api/ai-grade` 适配层。用户可在页面中填写 `API 接口`、`API Key`
和`模型 / 接入点 ID`，界面会根据接口域名、密钥格式和模型名识别厂商，并选择协议：

| 厂商 | 协议 | 图片扫描 | 联网参考 |
| --- | --- | --- | --- |
| OpenAI / GPT | Responses API | 支持 | 支持 Web Search |
| Google Gemini | generateContent | 支持 | 支持 Google Search |
| Anthropic / Claude | Messages API | 支持 | 当前不启用 |
| DeepSeek | Chat Completions | 仅聚合统计 | 当前不启用 |
| 豆包 / 火山方舟 | OpenAI 兼容 | 取决于模型 / 接入点 | 当前不启用 |
| OpenRouter、通义千问、Kimi、GLM、硅基流动、xAI、Mistral、Groq、Together 等 | OpenAI 兼容 | 根据模型名判断 | 当前不启用 |

页面提供 OpenAI、Gemini、Claude、DeepSeek 和豆包的快速配置，也允许填写其他公开
HTTPS OpenAI 兼容接口。自定义地址在服务端会拒绝 HTTP、内网地址、含密钥的网址参数
和跨域重定向，避免把接口变成任意网络代理。

用户填写的 API Key 只保存在当前 React 页面状态，刷新后清除；它通过 HTTPS 随单次
请求发送，服务端不会写入数据库、日志或浏览器存储。由于请求必须通过本站服务端适配
不同厂商的 CORS 与协议，部署者仍应使用可信的 Vercel 项目。

部署者也可以保留“站点默认 AI”，在 Vercel 项目的“设置 → 环境变量”中添加：

```text
OPENAI_API_KEY=你的 OpenAI API Key
OPENAI_VISION_MODEL=gpt-5.6
OPENAI_SEARCH_MODEL=gpt-5.6
```

重新部署后，用户可以选择“站点默认”，无需在页面填写自己的密钥。编辑器提供
“AI 智能复核”，LUT 工作台提供“AI 智能扫描”。两项功能都默认关闭：

- 单图复核上传原片与本地处理结果各一张低分辨率 JPEG；
- LUT 扫描最多上传 8 张均匀抽取的代表性 JPEG，全部照片仍由本地统计模型训练；
- AI 数值只以受限权重参与校准，本地直方图、色域和剪切检测仍是主模型；
- DeepSeek 等未确认视觉能力的文本接口不接收照片，只依据本地聚合统计复核；
- 视觉能力由模型决定的兼容接口会在页面显示识别结果，调用失败不会破坏本地模型。

### 联网参考匹配

LUT 工作台的“联网参考匹配”与“AI 智能扫描”相互独立。启用前者后，
系统会在本地照片统计完成后，将 LUT 名称和聚合后的阶调、色相、饱和度等摘要
发送给服务端；原始照片不会因此上传。联网参考当前支持 OpenAI Web Search 与
Gemini Google Search，其他厂商会在界面中禁用该开关。检索同名相机、胶片或风格时
优先采用以下资料：

1. 厂商官方产品说明、技术资料、官方色彩说明和官方样片；
2. 带有可复核样片与具体观察的专业摄影媒体和评测；
3. 多个独立摄影社区中反复出现的共识，仅作补充。

页面会显示匹配对象、置信度、提炼出的共识和实际来源链接。联网结果最多以
18% 权重参与 LUT 求解；名称含糊、来源不足或互相冲突时会自动降低权重，证据
不足则完全不修改 LUT。此功能不会下载或复制网上的专有 LUT，也不能仅凭成片
和文字评价测量相机传感器的真实光谱响应；它模拟的是可观察、可归纳的渲染特征。

Web Search / Google Search 会产生额外 API 工具调用费用。公开部署时应为各厂商项目
设置合理的用量上限；站点默认密钥必须保留在服务端，绝不要使用 `NEXT_PUBLIC_`
前缀。

## 参考成片 LUT 训练

“制 LUT”工作台采用无对照统计学习：照片会被逐张缩放取样，模型只保留聚合后的
直方图、OKLab 色彩分布、灰阶锚点和色相分区数据，随后立即释放原图像素。
最低要求为 12 张，推荐 24–50 张，数量没有程序硬上限。

由于没有原始照片对照，模型提取的是整组照片中反复出现的共同色彩特征，而不是
某一台相机的真实光谱响应。数据集应保持统一调色风格，并尽量覆盖肤色、天空、
植物、室内、日光和暗光。标准 3D LUT 可以记录全局颜色和阶调，但不能记录锐化、
降噪、颗粒、局部蒙版、景深或局部光照。
